# The downloadable arena (release)

pokeshell arena ships as a standalone download for people who don't use a terminal or pokeshell: a Windows exe and a
macOS app. Double-click it and the game opens in the browser, with 3 free booster packs to start a collection.

## What's in a release

| file | what |
|---|---|
| `pokeshell-arena-<version>-windows-x64.zip` | `pokeshell-arena/pokeshell-arena.exe` (one file, about 56 MB: the host with the whole game embedded) and `READ ME FIRST.txt` |
| `pokeshell-arena-<version>-macos-universal.zip` | `pokeshell arena.app` (Apple silicon and Intel, about 110 MB unzipped) and `READ ME FIRST.txt` |
| `SHA256SUMS.txt` | the zips' checksums |

The binary embeds everything the game needs (`release/arena-data.pak`, built by `tools/release/bundle.mjs`): the built
frontend with the battle sprites, the ten arena paintings and the sfx; pokeshell's card and booster data
(`pack.json`, `boosters.json`, `carddata.json`); and the face of every served card and its shiny form (about 2,300
images). Nothing is downloaded at run time, except the Google fonts the page asks for (offline it falls back to system
fonts). No PowerShell, no pokeshell, no install.

## How the standalone arena works

- **Its own wallet and packs.** The downloadable build always runs in standalone mode (`--features bundle` implies
  `--standalone`): it never looks for pokeshell, so a terminal user's pokeshell wallet and binder are never touched by
  it, and the Mac build has nothing to look for anyway. The host keeps its own wallet (`tokens.log`) and pulls
  (`pulls.log`) in the state folder and opens real boosters itself: `host/src/booster.rs` is a port of pokeshell's
  booster model (`scripts/lib/booster.ps1`, `Booster.cs`): the same slots, outcome weights (published rate x served /
  printed, the unserved share to the base outcome), set choice for a random pack (sealed pack price ^ -0.7), shiny roll
  (1 in 64), effects, hit sizes and reveal order. `host/src/parity.rs` checks the odds tables against what
  `pokeshell pack odds --json` printed for the same data (`host/tests/fixtures/pokeshell/`, regenerated by
  `npm run release:fixture` against a throwaway pokeshell state), and rolls 20,000 packs of every set against them.
  The JSON the page gets is pokeshell's shape (`collection --json` with `firstCaught` / `lastCaught` and counts,
  `pack open --json`, `pack sets --json`), so the frontend is the same in both modes.
- **3 starter packs.** The first time a state starts, the host writes a `+3` line with `kind=starter` to `tokens.log`.
  That line is the record: it's checked before granting, so the grant happens once per state, survives restarts and
  can't be repeated (`host/src/standalone.rs` tests it, including concurrent first starts). With no cards yet, the
  page shows a welcome card with an "Open a pack" button (you only battle with cards you own); after the first pack
  the pulled cards are the roster.
- **Tokens, 10 to a pack.** A win earns tokens: 1v1 1, team 2, +1 on hard, +2 on expert. Every 10 tokens make a pack;
  the rest carries over. The count is in `matches.jsonl` (each result's tokens minus 10 per pack it granted), so a
  replayed match counts once. The same rule applies with pokeshell (a pack is one `pokeshell pack grant 1`).
- **Double-click.** The exe/app is a launcher: if the arena is already running for this state it opens the browser
  on it, else it starts the host in the background and opens the browser. One host per state (a lock file). The host
  prefers port 47616, then a few fixed alternatives (51616, 53616, ...: the page keeps one origin, so its browser-stored settings survive a relaunch), then any free port. It exits about 2 minutes after the last game tab
  closes (a browser slows a background tab's timers to once a minute, so less would cut a backgrounded game off);
  launching again starts it again, and the page says so if it finds the host gone.
- **State** lives in the per-user app data folder, never next to the exe: `%LOCALAPPDATA%\pokeshell-arena-standalone`
  on Windows, `~/Library/Application Support/pokeshell-arena` on macOS (`$POKEARENA_STANDALONE_HOME` overrides it).
  Deleting it starts over (with new starter packs).
- A dev or terminal setup is unchanged: `arena-host` without `--standalone` uses pokeshell's wallet and collection.
  `arena-host --standalone --data release/bundle` (or `--data release/arena-data.pak`) runs the standalone mode from
  a checkout.

## Cutting a release

The code comes from the tagged commit; the art doesn't live in git (the battle sprites are pokemon-colorscripts art,
the arena paintings are generated from card scenes, the card faces are rendered from pokeshell's built card art), so
CI builds from an art pak that a dev machine uploads once and again whenever the art or pokeshell's card data changes.

1. **The art (once, and when it changes).** On a machine with the art in `public/` (`install.ps1`) and a pokeshell
   checkout next to this one with its built card art and `binder.exe`:
   ```powershell
   npm ci
   npm run build
   npm run release:art          # release/arena-art.pak (+ .sha256): sprites, arena art, card faces, card data
   gh release create arena-art release/arena-art.pak release/arena-art.pak.sha256 --prerelease `
     --title "arena art (build input)" --notes "The art the release workflow builds from. Not a game download."
   ```
   To replace it later: `gh release upload arena-art release/arena-art.pak release/arena-art.pak.sha256 --clobber`.
   (A different release name: set the repository variable `ARENA_ART_TAG`, or pass `art_tag` when running the
   workflow by hand.)
2. **The version.** Bump `version` in `package.json` and `host/Cargo.toml` (the exe's version info and the app's
   Info.plist come from them), commit.
3. **Tag and push.** `git tag v0.1.0 && git push origin v0.1.0`. `.github/workflows/release.yml` then:
   - **data** (Ubuntu): `npm ci`, downloads and checks `arena-art.pak`, unpacks its art into `public/`, typechecks,
     runs the unit tests (the slow bot ladder excluded), `npm run build`, `bundle.mjs --art` -> `arena-data.pak`;
   - **windows**: `cargo test` (wallet, starter packs, tokens, the pack-odds parity), the bundled build (icon and
     version info embedded), the zip, and `tests/test-standalone.ps1` on it;
   - **macos**: `cargo test`, both architectures joined with `lipo`, the `.app` (ad-hoc signed) zipped with `ditto`,
     and a smoke test of the launcher and the API;
   - **release**: a **draft** GitHub Release for the tag with both zips and `SHA256SUMS.txt`, the notes from
     `docs/release-notes.md`. Check it, then publish it.
   Running the workflow by hand (Actions > release > Run workflow) builds the artifacts without a release.

### Locally

```powershell
npm run release:win            # build + release:data + cargo build --features bundle + the zip, in release\
npm run test:standalone        # the exe end to end (temp state, own port, no browser) + the page in Chromium
```
`npm run release:mac` does the same on a Mac (both architectures, `lipo`, the `.app`, `ditto`). On Windows the host
compiles for macOS (`cargo check --target aarch64-apple-darwin` / `x86_64-apple-darwin` after `rustup target add`),
but can't link without Apple's SDK (CoreFoundation): CI is where the Mac build is linked and tested.

## First launch: the apps aren't signed

Neither build is code-signed, so each OS warns the first time. The steps are in each zip's `READ ME FIRST.txt` and
the release notes:

- **Windows** (SmartScreen, "Windows protected your PC"): click **More info**, then **Run anyway**. Once. Unzip first:
  an exe run from inside a zip is a temp copy.
- **macOS** ("can't be opened because Apple cannot check it for malicious software" / "unidentified developer"):
  right-click (Control-click) the app, **Open**, then **Open** again. On macOS 15 Sequoia and later that shortcut is
  gone: double-click once, then **System Settings > Privacy & Security**, "pokeshell arena was blocked" > **Open
  Anyway**, and confirm. Once. If macOS says the app "is damaged" (a quarantined app whose signature doesn't check
  out), `xattr -dr com.apple.quarantine "/Applications/pokeshell arena.app"` in Terminal clears it; the ad-hoc
  signature the workflow applies is there to avoid that.

## What signing would take (not done)

- **macOS: Developer ID + notarization.** An Apple Developer Program membership ($99/year). A "Developer ID
  Application" certificate exported as a .p12 into the workflow (secrets: the base64 .p12 and its password, imported
  into a temporary keychain). Sign with the hardened runtime: `codesign --force --options runtime --timestamp --sign
  "Developer ID Application: <name> (<team id>)" "pokeshell arena.app"` (the app needs no entitlements: it serves
  127.0.0.1 and opens a URL). Notarize the zip with `xcrun notarytool submit <zip> --apple-id <id> --team-id <team>
  --password <app-specific password> --wait` (or an App Store Connect API key: secrets for the key id, issuer and .p8),
  then `xcrun stapler staple "pokeshell arena.app"` and zip it again. Then it opens with a double-click, no warning.
  A .dmg would want the same signing and stapling.
- **Windows: Authenticode.** A code-signing certificate: an OV certificate (from a CA, on a hardware token or a cloud
  HSM since 2023, about $200-400/year) still shows SmartScreen until the file builds reputation; an EV certificate or
  Microsoft's Trusted Signing / Azure Artifact Signing (a monthly subscription, identity validation) gets reputation
  faster. In CI: `signtool sign /fd sha256 /tr http://timestamp.digicert.com /td sha256 ...` with the cloud signing
  provider's action, on `pokeshell-arena.exe` before it's zipped.
- Neither changes the code; both are steps in `release.yml` between the build and the zip.

## Notes for a public repository

- The art is copyrighted (Pokémon sprites and card art belong to Nintendo / The Pokémon Company / Creatures / Game
  Freak; the arena paintings are generated from card scenes). It isn't in git, but it is in the release downloads and
  in the `arena-art` release asset, the same way pokeshell's own art release ships it. It's a fan project; the zips'
  READ ME and the README say so.
- `host/tests/fixtures/pokeshell/` holds copies of pokeshell's tracked `pack.json` / `boosters.json` (card names,
  numbers, rarities; pokeshell's repository is public) and the odds tables, so the parity test runs anywhere.
